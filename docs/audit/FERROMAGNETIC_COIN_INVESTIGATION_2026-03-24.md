# CoinTrace — Технічне розслідування: DRDYB=1 з феромагнітними монетами

**Тип документа:** Аудит апаратно-програмної взаємодії  
**Дата розслідування:** 2026-03-24  
**Статус:** Завершено. Висновок — архітектурне рішення прийнято. Зовнішній аудит отримано та опрацьовано 2026-03-24.
**Зовнішній аудит:** `docs/external/AUDIT_FERROMAGNETIC_INVESTIGATION.2026-03-24.md`  
**Автори:** Embedded-команда CoinTrace  
**Платформа:** ESP32-S3FN8 / M5Stack Cardputer-ADV + LDC1101 Click Board (MIKROE-3240)

---

## 1. Контекст

Після успішного завершення апаратної сесії S-4 (підтверджено fSENSOR=909.2 kHz, L=36042, ADR-CLKIN-002 закрито) команда перейшла до першого практичного тестування детекції монет. В якості тестового об'єкта використовувалась монета з цинковим ядром і нікелевим покриттям.

**Параметри тестової монети:**
- Матеріал: цинкове ядро (Zn) + нікелева обкладка (Ni)
- Маса: 6.4 г
- Діаметр: 23.5 мм
- Товщина: 2.3 мм

**Параметри котушки MIKROE-3240:**
- Діаметр котушки: 24 мм
- Резонансний конденсатор C4: 330 pF
- Розрахована індуктивність L: ≈ 92.8 μH
- fSENSOR (без монети): 909.2 kHz

## 2. Спостережені симптоми

### 2.1 Сценарій A — Монета по центру котушки, без спейсера (d ≈ 0.1 мм)

Монета діаметром 23.5 мм покриває 97.9% площі котушки 24 мм, лежачи безпосередньо на поверхні. Зазор між монетою і котушкою = товщина захисного лаку PCB, ≈ 0.1 мм.

**Симптом:** одноразова детекція присутності (RP спрацьовує), після чого система «замерзає» з потоком попереджень:

```
[42970ms] INFO  LDC1101  | Coin PRESENT (RP=39317, baseline=57344, ratio=0.69)
[43766ms] WARN  LDC1101  | DRDYB=1 for 11 consecutive update() calls — conversion frozen?
[43793ms] WARN  LDC1101  | DRDYB=1 for 12 consecutive update() calls — conversion frozen?
... (зростає до 17+ і не зупиняється)
```

L_DATA при цьому не зчитується — конверсія ніколи не завершується. Жодного запису вимірювання не зберігається.

**Важливо:** `DRDYB=1`, **не** `STATUS_NO_OSC` — котушка продовжує коливатись, але LDC1101 не завершує конверсію L_DATA.

### 2.2 Сценарій B — Монета перекриває половину котушки, без спейсера

Монета зміщена так що перекриває ≈50% площі котушки.

**Результат:** Clean detect, збережено запис.

```
[36001ms] INFO  LDC1101  | Coin PRESENT (RP=43690, baseline=57344, ratio=0.76)
[42849ms] INFO  LDC1101  | Coin REMOVED (RP=56173, baseline=57344, ratio=0.98)
[42926ms] INFO  Meas     | Saved #13 — RP=56173 L=8863 ts=42s
```

### 2.3 Сценарій C — Велика монета в пластиковій капсулі (d ≈ 1 мм), по центру

Монета в стандартній нумізматичній капсулі, діаметр виступає за краї котушки. Зазор = товщина стінки капсули ≈ 1 мм.

**Результат:** Повна детекція без попереджень, запис збережено.

## 3. Root Cause Analysis

### 3.1 Встановлена причина: замкнений магнітний ланцюг (Closed Magnetic Circuit)

Феромагнітна монета (нікель: μr ≈ 100–600 при кімнатній температурі) за відсутності повітряного зазору веде себе як **кришка pot-core трансформатора**:

```
Без зазору (d ≈ 0):

  ╔═══════════════════════════════╗   ← Нікелева обкладка (μr ≈ 600)
  ╚═══════════════════════════════╝
  ████████████████████████████████   ← Котушка MIKROE-3240

Весь магнітний потік замикається крізь нікель.
L_coil × μr_eff → L зростає в ~μr_eff разів.
```

```
З повітряним зазором (d ≥ 1 мм):

  ╔═══════════════════════════════╗
  ╚═══════════════════════════════╝
         ↑↑↑ повітряний зазор ↑↑↑
  ████████████████████████████████

Зазор "розмикає" ланцюг. μr_eff ≈ 1–5.
L повертається до нормального діапазону.
```

Внаслідок цього fSENSOR падає далеко нижче робочого діапазону LDC1101:

$$f_{SENSOR,coin}(d=0) = \frac{f_{SENSOR,baseline}}{\sqrt{\mu_{r,eff}}} \approx \frac{909\ \text{kHz}}{\sqrt{100{-}600}} \approx 37{-}91\ \text{kHz}$$

### 3.2 Два незалежних блокувальних механізми LDC1101

При fSENSOR нижче порогів LDC1101 запускаються два незалежні апаратні механізми, що блокують завершення конверсії L_DATA:

#### Механізм 1 — L_DATA 16-bit Overflow (RESP_CYCLES)

L_DATA — 16-бітний лічильник, який рахує цикли fCLKIN за `RESP_CYCLES` тактів fSENSOR:

$$L_{DATA} = \frac{f_{CLKIN} \times RESP\_CYCLES}{3 \times f_{SENSOR}}$$

При RESP_CYCLES=6144 (resp_time_bits=7, максимальна якість):

$$f_{SENSOR,min} = \frac{16{,}000{,}000 \times 6144}{3 \times 65535} \approx 500\ \text{kHz}$$

→ Якщо fSENSOR < 500 kHz, L_DATA > 65535, переповнення — конверсія ніколи не завершується.

#### Механізм 2 — Watchdog MIN_FREQ (DIG_CONFIG[7:4])

> *(Уточнено за зауваженням B зовнішнього аудиту)*

DIG_CONFIG[7:4] задає мінімальну частоту watchdog-таймера згідно з формулою datasheet §8.6.5:

$$f_{SENSOR,min} = \frac{8\ \text{MHz}}{16 - \text{nibble}}$$

| nibble | fSENSOR_min | Призначення |
|---|---|---|
| 0x0 | 500 kHz | малі котушки, висока fSENSOR |
| 0x7 | **889 kHz** | ← оптимально для MIKROE-3240 (909 kHz) |
| 0xD | **2.67 MHz** | MikroE SDK default (для маленьких котушок) |
| 0xF | 8.0 MHz | watchdog занадто агресивний → NO_OSC при 909 kHz |

Watchdog функціонує не як жорсткий frequency gate, а як **таймер очікування**: при fSENSOR < fSENSOR_min watchdog вважає що осцилятор "зупинився" і безперервно перезапускає конверсію → DRDYB=1 перманентно.

При nibble=0xD (2.67 MHz) і стабільному fSENSOR=909 kHz watchdog НЕ спрацьовує в нормальному режимі (підтверджено hw-тестом: L_baseline незмінний). Але при різкому падінні fSENSOR (монета d=0) watchdog тригерить негайно.

Цей механізм не залежить від RESP_CYCLES.

#### Чому в Сценарії A обидва спрацьовують одночасно

| Механізм | Поріг | Стан при d=0 (fSENSOR≈37-91 kHz) |
|---|---|---|
| L_DATA overflow (bits=7) | 500 kHz | ❌ БЛОКУЄ |
| MIN_FREQ watchdog (nibble=0xD) | 2.67 MHz (таймер) | ❌ БЛОКУЄ |
| L_DATA overflow (bits=5) | 125 kHz | ❌ БЛОКУЄ |
| L_DATA overflow (bits=3) | 31 kHz | ✅ overflow не виникає |
| MIN_FREQ watchdog (nibble=0xF) | 8.0 MHz | ❌ БЛОКУЄ навіть без монети |

### 3.3 Роль skin depth нікелю

> *(Додано за зауваженням F-03 зовнішнього аудиту)*

При fSENSOR=909 kHz глибина проникнення (skin depth) для різних металів:

| Метал | δ (мкм) | Висновок |
|---|---|---|
| Нікель Ni | **10 μm** | Поле повністю поглинається в покритті 20-50μm |
| Цинк Zn | 128 μm | Поле проникає крізь нікель у ядро |
| Срібло Ag | 67 μm | Стандартний eddy current ефект |

При d=0 **тільки нікелеве покриття** визначає поведінку — vихрові струми у цинковому ядрі практично відсутні (поле до нього не доходить). Саме тому тонке нікелеве покриття спричиняє настільки драматичний pot-core ефект.

### 3.4 Чому Сценарій B (50% покриття) працює

При 50% покритті площі котушки нікелевий ланцюг не замикається повністю. Домінує ефект вихрових струмів (в 
нікелевому покритті та цинковому ядрі через непокриту половину, μr(Zn)=1):

- Ефективне μr_eff → 1 (магнітний ланцюг розімкнений через непокриту половину)
- Vихрові струми зменшують L (а не збільшують)
- fSENSOR ≈ 924 kHz (навіть трохи вища baseline — eddy currents домінують)

### 3.5 Чому Сценарій C (капсула, d=1 мм) працює

> *(Модель уточнена за зауваженням F-02 зовнішнього аудиту)*

Повітряний зазор є **домінантним елементом магнітного опору (reluctance)** в ланцюгу. Модель reluctance circuit:

$$\mu_{r,eff}(d) \approx \frac{\mu_r \cdot t_{Ni}}{t_{Ni} + d_{air} \cdot \mu_r}$$

Де $t_{Ni}$ — ефективна товщина нікелевого покриття (~50 μm), $d_{air}$ — повітряний зазор.

| d (мм) | μr_eff | fSENSOR |
|---|---|---|
| 0 | ~200–600 | ~37–91 kHz ← DRDYB |
| 1 | ~1–5 | ~800–900 kHz ✅ |
| 2 | ~1 | ~909 kHz (≈ baseline) ✅ |

Перевід між "не працює" і "працює" **різкий**, а не плавний — бо навіть мінімальний зазор стає домінантним reluctance елементом і знижує μr_eff з сотень до одиниць. Це стандартна поведінка трансформатора з зазором.

## 4. Хронологія спроб виправлення

| # | Дія | DIG_CONFIG | Результат | Висновок |
|---|---|---|---|---|
| 1 | resp_time_bits: 7 (baseline) | 0xD7 | d=0: DRDYB=1 | overflow 500kHz |
| 2 | resp_time_bits: **5** | 0xD5 | d=0: DRDYB=1 | overflow 125kHz |
| 3 | resp_time_bits: **3** | 0xD3 | d=0: DRDYB=1 | fSENSOR < 118kHz → MIN_FREQ halt |
| 4 | resp_time_bits: 3 + min_freq_nibble: **15** | 0xF3 | **NO_OSC навіть без монети** | nibble=0xF → fSENSOR_min=8MHz, watchdog тригерить негайно при 909 kHz |
| 5 | resp_time_bits: **7** (повернення) | 0xD7 | d=1mm: ✅ OK | **спейсер вирішує проблему** |
| 6 | min_freq_nibble: **7** (F-01) | 0x77 | d=1mm: ✅ OK, L=36043 | watchdog threshold=889 kHz — точно під fSENSOR |

**Висновок з хронології:** проблема d=0 для феромагнітних монет є **принциповою фізичною** — вона не вирішується програмно на рівні RESP_CYCLES без руйнування нормального режиму роботи сенсора.

## 6. Зміни у кодовій базі

### `lib/LDC1101Plugin/src/LDC1101Plugin.h`

Додано поле `minFreqNibble_` для конфігурабельного MIN_FREQ threshold:

```cpp
// Нове поле (default = 0x0D — зберігає сумісність з MikroE SDK)
uint8_t  minFreqNibble_ = 0x0D;

// Завантаження з конфігу
minFreqNibble_ = ctx_->config->getUInt8("ldc1101.min_freq_nibble", 0x0D);

// DIG_CONFIG тепер параметричний (раніше hardcoded 0xD0 | resp_bits)
uint8_t digCfg = ((minFreqNibble_ & 0x0F) << 4) | (respTimeBits_ & 0x07);
```

Покращений лог DRDYB включає STATUS байт для діагностики:
```cpp
"DRDYB=1 for %lu consecutive calls — STATUS=0x%02X (check MIN_FREQ/RESP_TIME)"
```

**Примітка:** `min_freq_nibble: 7` додано до `ldc1101.json` за результатами hw-верифікації F-01 (2026-03-24). default у коді залишено 0x0D для зворотної сумісності.

## 7. Архітектурне рішення: ADR-SPACER-001

**Назва:** Мінімальний повітряний зазор для феромагнітних монет  
**Статус:** ПРИЙНЯТО 2026-03-24  
**Рішення:**

> **CoinTrace вимагає мінімального повітряного зазору d_min ≥ 1.5 мм між монетою і котушкою для всіх монет, що містять феромагнітні метали (нікель, залізо, кобальт, феромагнітні сплави).**
>
> *(Підвищено з 1 мм до 1.5 мм за рекомендацією зовнішнього аудиту — запас на виробничі допуски лотка та варіацію товщини Ni plating між монетами)*

**Обґрунтування:**

При d < 1 мм феромагнітні монети замикають магнітний ланцюг котушки. Ефективне μr_eff > 100 знижує fSENSOR до <100 kHz, що виходить за операційний діапазон конфігурації LDC1101.

**Наслідки для конструкції:**

| Елемент | Вимога |
|---|---|
| Лоток/тримач монети | Висота поверхні над котушкою **≥ 1.5 мм** (рекомендовано 2 мм) |
| Матеріал дна лотка | Немагнітний (пластик, алюміній, картон) |
| Товщина дна лотка | 1–3 мм — оптимально (відповідає товщині капсул) |
| Верхня межа зазору | ≤ 6 мм (вище — значна втрата сигналу RP) |
| Ідеальний зазор | **2–3 мм** (максимальний RP сигнал при стабільному L) |

**Що НЕ потрібно:**
- Спейсери між вимірюваннями різних монет (зазор фіксований у конструкції)
- Програмна компенсація d=0 (фізично неможлива для цього класу монет)

## 8. Вплив на C-2 (Multi-position Calibration)

В архітектурі C-2 передбачено вимірювання на 4 позиціях:
```
STEP_0(0mm) → STEP_1(1mm) → STEP_3(3mm) → STEP_DRIFT(0mm)
```

**Проблема:** `STEP_0(0mm)` для феромагнітних монет дає неправильні і нестабільні значення L_DATA.

**Рекомендоване рішення:** Змінити STEP_0 на базовий зазор конструкції (1 мм = товщина дна лотка) і використовувати абсолютні відстані від нижньої стінки:

```
STEP_base(d=1mm) → STEP_1(d=2mm) → STEP_2(d=4mm) → STEP_DRIFT(d=1mm)
```

Або, при фіксованій конструкції лотка з d_bottom=2 мм:
```
STEP_0(d=2mm) → STEP_1(d=4mm) → STEP_2(d=6mm) → STEP_DRIFT(d=2mm)
```

**Це архітектурне рішення потребує узгодження до початку реалізації C-2.**

## 10. Ключові висновки для зовнішнього аудитора

1. **LDC1101 не призначений для вимірювання феромагнітних монет при d=0.** Це не баг прошивки — це апаратне обмеження, яке слід задокументувати в специфікації продукту.

2. **Симптом DRDYB=1 storm має дві незалежні причини** — overflow лічильника та апаратний MIN_FREQ halt. Усунення однієї без другої не вирішує проблему.

3. **Значення nibble=0xF є небезпечним** — fSENSOR_min=8 MHz, watchdog вважає 909 kHz "зупиненим осцилятором" і безперервно тригерить NO_OSC. Це очікувана поведінка при неправильному налаштуванні (підтверджено hw і пояснено формулою datasheet §8.6.5).

4. **Спейсер 1 мм повністю вирішує проблему.** Конструктивний зазор є стандартною практикою для LDC-сенсорів — TI Application Note SNOA944 рекомендує зазор 2–5 мм для типових застосувань.

5. **Кодова база залишається стабільною.** Всі зміни прошивки обмежені параметризацією існуючої логіки — жодних breaking changes в архітектурі плагіна.
